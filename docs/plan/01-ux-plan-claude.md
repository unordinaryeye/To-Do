## 0. 요약 (한 페이지)

**현재 앱**은 "카테고리별 루틴 체크 + 오늘의 할 일"을 단일 화면에 넣은 구조다. 참고 앱은 "습관(반복) / 투두(일회성)"를 분리하고, 습관마다 **트리거(언제)**, **반복 주기**, **목표 태그**를 붙이며, 주간 행에 **날짜별 달성률 도넛**과 **초록불**을 표시하고, 별도의 **통계** 탭을 가진다.

이번 리뉴얼의 핵심 결정 5가지:

1. **하단 탭바 4개**: 홈 / 통계 / 목표 / 내정보. 참고 앱의 추천·소셜·멤버십은 제외하고, 만다라트를 담을 "목표" 탭을 신설한다.
2. **홈은 참고 앱 구조를 그대로 채택**: 주간 행(도넛) → 루틴/투두 세그먼트 탭 → 필터 행 → 표 형태 목록 → FAB.
3. **요일별 반복(D)은 P0**: 달성률·스트릭·주간 도넛·통계 전부의 분모를 바꾸는 기반 기능이므로 가장 먼저 넣는다.
4. **4분면 매트릭스(A)는 투두 탭의 "보기 전환"**, **만다라트(B)는 목표 탭의 목표 상세**, **할일 시간(C)은 투두 폼 필드 + 시간 셀**, **요일 반복(D)은 습관 폼의 반복 주기 필드**로 들어간다.
5. **릴리스 3단계**: R1 뼈대(P0) → R2 목표·통계·매트릭스(P1) → R3 만다라트·알림·확장(P2).

## 2. 새 정보구조(IA)

### 2.1 하단 탭바

```
┌──────────┬──────────┬──────────┬──────────┐

| 탭 | 역할 | 포함 화면 |

- 카테고리 그룹 헤더는 제거하고 번호 열로 대체한다. 목표별 그룹 보기는 ≡ 정렬 메뉴의 옵션으로 제공한다.

## 3. 추가 기능 4개 상세 UX 흐름

### 3.1 (A) 4분면 매트릭스 — 아이젠하워

**어디에**: 홈 > 투두 탭의 보기 전환 토글 `[☰ 리스트 | ⊞ 매트릭스]`. 별도 탭이나 화면을 만들지 않는다. 이유: 매트릭스는 "오늘의 투두를 다른 각도로 보는 것"이지 다른 데이터가 아니다. 선택한 날짜·기간 필터(하루/주)를 그대로 공유한다.

**데이터**: 투두에 `urgent:boolean`, `important:boolean` 두 값을 추가한다. 사분면은 파생값이다.

| urgent | important | 사분면 | 라벨 | 권장 행동 |
|---|---|---|---|---|
| true | true | Q1 | 🔥⭐ 지금 하기 | 즉시 |
| false | true | Q2 | ⭐ 계획하기 | 시간 지정 유도 |
| true | false | Q3 | 🔥 위임/빨리 끝내기 | 짧게 처리 |
| false | false | Q4 | 나중에/버리기 | 삭제 후보 |
| null | null | 미분류 | 미분류 | 하단 보관함 |

**진입점 3곳**
1. 투두 탭 상단 `[⊞]` 토글 → 매트릭스 보기. 마지막 선택을 localStorage에 기억한다.
2. 투두 폼의 "우선순위" 행: (🔥 긴급)(⭐ 중요) 토글 칩. 리스트 보기에서도 뱃지로 반영된다.
3. 투두 액션 시트의 "사분면 이동 ›" → 2×2 미니 피커.

**매트릭스 화면 상호작용**
- 각 사분면 셀은 헤더(라벨 + 개수) + 항목 리스트 + "+ 추가" 버튼. "+ 추가"로 만든 투두는 그 사분면 값이 프리필된다.
- 항목 체크: 체크박스 탭. 완료 항목은 취소선 후 셀 하단으로 내려간다.
- 항목 이동: 드래그 앤 드롭(Pointer Events)으로 다른 사분면에 놓으면 urgent/important를 재계산해 저장한다. 드래그가 어려운 환경을 위해 항목 길게 누르기 → 사분면 피커 폴백을 둔다.
- 미분류 보관함: 기존 투두와 빠른 입력으로 만든 투두가 모인다. "사분면에 넣기" 버튼으로 피커를 연다. 매트릭스를 처음 켜면 보관함이 비어 있지 않은 한 안내 토스트 "미분류 3개를 사분면에 배치해 보세요"를 띄운다.
- 빈 사분면은 흐린 안내 문구를 보여준다 (예: Q4 "여기 있는 일은 정말 필요한지 다시 생각해 봐요").

**리스트 보기와의 관계**: 리스트에서 사분면은 뱃지(🔥/⭐)와 정렬 2차 키로만 쓰인다. 시간(C)이 1차 키다. 즉 "시간이 정해진 일은 시간순, 나머지는 중요·긴급순"이다.

**기간 필터**: "주" 보기에서는 매트릭스가 그 주의 모든 투두를 모아 보여주고, 항목 앞에 요일 약어(수)를 붙인다. 주간 계획을 매트릭스로 세우는 용도다.

**통계 연결(P1)**: 월간 통계 하단 투두 카드에 "지금 하기(Q1) 완료율", "Q4 삭제/이월 수"를 노출한다.

### 3.2 (B) 만다라트 (9×9)

**어디에**: 목표 탭 > 목표 상세. 만다라트의 중앙 핵심 목표 = 목표 태그 1개. 즉 목표 태그마다 최대 1개의 만다라트가 붙는다. 만다라트가 없는 목표는 "만다라트 만들기" 빈 상태 카드를 보여준다.

**모바일에서 9×9를 보는 방식**: 81칸을 한 화면에 넣지 않는다. 두 단계 줌으로 푼다.
- 1단계 개요(3×3): 중앙 = 핵심 목표(태그명), 주변 8칸 = 세부목표. 각 칸에 이번 달 달성률(연결 습관 평균)이 배경 채움으로 표시된다.
- 2단계 확대(3×3): 세부목표 1개를 탭하면 그 세부목표가 중앙, 주변 8칸 = 실천항목. 좌우 스와이프로 인접 세부목표로 이동한다. 상단 [표] 버튼은 9×9 전체를 가로 스크롤 표로 보여주는 읽기 전용 뷰(공유/캡처 용도).

**셀 편집 흐름**
1. 개요에서 [편집] → 편집 모드. 빈 칸은 점선, 탭하면 인라인 입력.
2. 확대 화면에서 실천항목 칸 탭 → 셀 시트:
   ```
   ┌ 실천항목 ───────────────────────┐
   │ [ 달리기 30분              ]    │
   │ 🔗 연결된 습관: 🏃 30분 운동 (90%) │  ← 없으면 아래 두 버튼
   │ [ 습관으로 만들기 ] [ 투두로 만들기 ]│
   │ [ 기존 습관 연결 › ]              │
   │ 삭제                            │
   └─────────────────────────────────┘
   ```
3. "습관으로 만들기" → 습관 폼이 열리고 이름·이모지·목표 태그·`mandalaRef`가 프리필된다. 저장하면 셀에 🔗가 붙는다.
4. "투두로 만들기" → 투두 폼 프리필(이름, 오늘 날짜, 중요=true). 일회성 실천항목용.
5. "기존 습관 연결" → 해당 목표 태그의 습관 목록에서 선택.

**데이터 연결 규칙**
- 습관 쪽에 `mandalaRef:{goalId, subIndex(0..7), actionIndex(0..7)}`를 저장한다. 만다라트 셀은 텍스트만 가진다(단방향 참조로 삭제 안전성 확보).
- 셀 달성률 = 연결 습관의 해당 월 달성률(6장 정의). 세부목표 달성률 = 연결된 실천항목들의 평균. 핵심목표 달성률 = 통계의 목표 달성률과 동일 값.
- 습관을 삭제하면 셀의 🔗만 사라지고 텍스트는 남는다. 셀을 삭제하면 습관의 `mandalaRef`를 null로 지운다.

**홈에서의 노출**: 홈 습관 행에는 만다라트 표시를 넣지 않는다(정보 과밀). 습관 액션 시트 상단 요약줄에 "🔗 건강 › 운동 › 달리기"를 한 줄 추가한다.

**빈 상태 온보딩**: 목표 탭이 비어 있으면 "목표 태그를 먼저 만들어요 → 만다라트로 쪼개요 → 실천항목을 습관으로 보내요" 3단계 그림 안내.

### 3.3 (C) 할 일에 시간 추가

**어디에**: 투두 폼의 "🕒 시간" 행, 투두 표의 2번째 열(시간 셀), 리스트 정렬 키.

**입력**
- `<input type="time">` 네이티브 사용(iOS 휠 피커). "지정 안 함" 토글로 null 처리.
- 빠른 입력창에서 `14:00 병원`, `오후 2시 병원`, `2pm 병원` 형태를 파싱해 시간과 이름을 분리한다(P1). 파싱 결과는 입력창 아래에 미리보기 칩으로 보여주고, 잘못 파싱됐으면 칩을 탭해 지운다.

**표시**
- 시간 셀: `HH:MM` 24시간 표기(내정보에서 12시간 옵션, P2). 시간 없으면 `–`.
- 지난 시간 + 미완료 + 선택일이 오늘: 시간 텍스트 빨강 + `!`. 완료되면 회색.
- 선택일이 오늘일 때 현재 시각 위치에 얇은 "지금" 구분선을 그린다(P1).

**정렬**: 시간 있는 항목 오름차순 → 시간 없는 항목(사분면 → 수동 순서). 수동 ▲▼/드래그는 시간 없는 항목끼리만 허용한다. 시간 있는 항목을 옮기려 하면 "시간을 바꿔 순서를 조정해요" 토스트.

**이월**: 지난 날짜의 미완료 투두는 자동 이월하지 않는다. 대신 홈 투두 탭 상단에 "어제 못 끝낸 일 2개 › 오늘로 옮기기" 배너를 띄운다(P1). 옮길 때 시간은 유지한다.

**습관과의 관계**: 습관의 "언제 할래요"가 시간 타입이면 루틴 탭 트리거 열도 같은 `HH:MM` 스타일로 그려 일관성을 맞춘다.

### 3.4 (D) 루틴 요일별 반복

**어디에**: 습관 폼의 "📅 반복 주기" 행(W-7 시트). 홈 루틴 탭의 노출 필터. 모든 달성률·스트릭·통계 계산의 분모.

**데이터**: `repeat:{type:'daily'|'weekly', days:[0..6]}`. `daily`는 `days:[0,1,2,3,4,5,6]`과 동치로 정규화해 저장한다(계산 코드 단순화). 기존 습관은 마이그레이션 시 `daily`.

**"해당 날짜에 예정된 습관" 판정 함수 (모든 계산의 기준)**
```
isScheduled(habit, date) =
  date >= habit.startDate
  && (habit.endDate == null || date <= habit.endDate)
  && !isPaused(habit, date)
  && habit.repeat.days.includes(weekday(date))
```
- `startDate`: 습관 생성일. 생성 이전 날짜에는 존재하지 않는 것으로 취급해 과거 달성률이 왜곡되지 않게 한다.
- `endDate`: "끝내기" 실행일. 이후 날짜에서 제외. 통계에서는 기간 내 기록이 보인다.
- `isPaused`: "쉬어가기" 기간(`pauses:[{from,to}]`) 안이면 제외.

**계산 규칙**

| 지표 | 정의 |
|---|---|
| 날짜 달성률(주간 도넛) | 그날 `isScheduled`인 습관 중 체크된 수 / 예정 수. 예정 0이면 도넛 없음(빈 원) |
| 초록불 | 예정 수 ≥ 1이고 달성률 100% |
| 전체 스트릭 | 오늘(또는 어제)부터 거꾸로 가며 초록불이면 +1. **예정 습관이 0인 날은 건너뛴다**(끊기지도, 늘지도 않음). 오늘이 아직 미완이면 어제부터 센다(현재 코드 동작 유지) |
| 습관별 스트릭 | 그 습관이 예정된 날만 따라가며 연속 체크 수. 예정 아닌 날은 건너뜀 |
| 월간 달성률(통계) | 이번 달 1일~오늘(또는 말일) 중 예정일에 체크한 수 / 예정일 수 |

**홈 노출 규칙**
- 루틴 탭 기본: 선택일에 `isScheduled`인 습관만 표시.
- "하루 ▾" 메뉴에 "예정 안 된 습관도 보기" 토글. 켜면 회색 행으로 하단에 표시하고 체크 셀은 비활성(탭하면 "오늘은 예정에 없는 습관이에요. 그래도 체크할까요?" 확인 → 예외 체크 허용. 예외 체크는 분모에 넣지 않고 분자에도 넣지 않되, 통계 그리드에 점선으로 표시).
- 예정된 습관이 0인 날: 루틴 탭 빈 상태 "오늘은 쉬는 날이에요 🛌. 투두를 확인해 볼까요?" + 투두 탭 이동 버튼.

**폼 UX**
- 반복 주기 행 값 텍스트: 매일 / "매주 월·수·금" / "평일" / "주말"(집합이 정확히 일치할 때 축약).
- 요일 칩은 내정보의 "주 시작 요일" 설정을 따라 배열한다.
- 요일 0개 선택 시 확인 버튼 비활성 + 인라인 메시지.
- 기존 습관의 반복 요일을 바꾸면 "오늘부터 적용돼요. 지난 기록은 그대로 남아요" 안내. 과거 기록은 보존하고 과거 달성률 계산은 기록 당시 예정 여부를 알 수 없으므로 **현재 반복 설정을 소급 적용**한다(단순화. 릴리스 노트에 명시).

**주간 행과의 상호작용**: 요일 반복 덕분에 주간 행 각 요일의 도넛 분모가 달라진다. 예정 0인 날은 빈 원으로 그려 "쉬는 날"임을 드러낸다.

### 4.2 하단 버튼과 상태

| 상황 | 버튼 라벨 | 활성 조건 |
|---|---|---|
| 추가 | 시작하기 | 이름 유효 + 반복 요일 ≥ 1 |
| 수정 | 저장하기 | 위 조건 + 원본과 1개 이상 변경 |
| 복사 | 복사하기 | 추가와 동일. 이름 뒤에 " (복사)" 프리필, 기록은 복사하지 않음 |

- 뒤로가기(‹) 시 변경사항이 있으면 "작성 중인 내용을 버릴까요?" 확인.
- 저장 후 홈으로 복귀하며 토스트 "☀️ 기상 시간 기록 습관을 시작했어요". 새 습관 행은 하이라이트 애니메이션.
- 수정 시 삭제는 폼 안에 두지 않고 액션 시트에만 둔다(오터치 방지).

### 4.3 현재 카테고리의 처리

현재 `category`(morning/work/health/evening/selfcare/study)는 폼에서 제거한다. 마이그레이션에서 6개 카테고리를 같은 이모지·색상의 **목표 태그 6개로 변환**하고 각 습관의 `goalIds`에 넣는다. 아침/저녁 같은 시간대 의미는 트리거("일어나자마자", "자기 전")로 옮기라는 안내 배너를 R1 첫 실행 시 한 번 띄운다.

## 5. 통계 화면 정의

### 5.1 공통

- 상단 세그먼트: 월간 / 주간 / 초록불. 마지막 탭 기억.
- 기간 이동: ‹ › 버튼 + 좌우 스와이프. 미래 기간은 비활성.
- 목표 칩 필터: (전체) + 목표 태그. 단일 선택. 선택 시 해당 태그 습관만 집계.
- 데이터가 없는 기간: 빈 상태 일러스트 + "이 달엔 기록이 없어요".
- 모든 계산은 3.4절 `isScheduled` 기준. 예외 체크(예정 아닌 날 체크)는 그리드에 점선 테두리로만 표시하고 비율에는 넣지 않는다.

### 5.2 월간 탭

| 섹션 | 내용 | 계산 |
|---|---|---|
| 목표 달성률 카드 | 큰 % + 진행 바 + "초록불 N일 · 최장 연속 M일" | (선택 태그 습관들의 예정일 중 체크 수) / (예정일 수). 기간은 1일~오늘(과거 달이면 말일) |
| 습관별 카드(2열 그리드) | 이모지+이름, 1~말일 그리드(7열, 1일의 요일에 맞춰 시작), 🕓달성률%, ✔달성 횟수 | 셀 색: 체크=습관 색 채움, 예정+미체크=연한 회색, 예정 아님=빈칸(테두리만), 미래=점 |
| 투두 카드 | 완료/등록 수, Q1 완료율, 시간 지정 준수율(시간 전에 완료한 비율) | todos 월 집계 |
| 정렬 | 달성률 내림차순. ≡ 메뉴에서 이름순/순서순 | - |

- 습관 카드 탭 → 습관 액션 시트의 "월간 기록"과 같은 상세(큰 그리드 + 요일별 달성률 막대 + 스트릭 히스토리).
- 습관별 색상: 목표 태그 색을 따르고, 태그가 없으면 인덱스 기반 팔레트 8색 순환.

│ 월 100% ▇▇▇▇▇  화 50% ▇▇▇  수 100% ▇▇▇▇▇│
└────────────────────────────────────────┘
```
- 주 시작 요일은 내정보 설정을 따른다.
- 행 탭 → 해당 습관 월간 기록.

### 5.4 초록불 탭

```
┌────────────────────────────────────────┐
│        ‹   2026년 9월   ›               │
│ 이번 달 초록불 12일 · 현재 연속 5일 · 최장 7일│
│  월  화  수  목  금  토  일              │
│   1● 2● 3◔ 4● 5○ 6○ 7●                │  ← ● 초록불 ◔ 부분 ○ 0% ─ 예정 없음
│  8● 9◑ 10 11 12 13 14                  │
│ ...                                    │
│ 최근 12개월 초록불 추이  ▁▃▅▇▆▇▇        │  ← 월별 초록불 일수 미니 막대
└────────────────────────────────────────┘
```
- 날짜 셀 탭 → 홈으로 이동해 그 날짜를 선택(과거 기록 수정 경로).
- 초록불 탭은 목표 칩 필터를 받지 않는다(하루 전체 기준의 개념이므로). 필터 행을 숨긴다.

### 5.5 성능 메모

- 월간 집계는 `checks` 객체를 날짜 키로 한 번만 순회해 `{habitId:{scheduled,done}}` 맵을 만든다. 습관 수 × 31일 규모이므로 매 렌더 계산해도 되지만, 통계 탭 진입 시 한 번 계산해 메모이즈하고 checks 변경 시 무효화한다.

## 6. 기능 우선순위와 릴리스 단위

### 6.1 우선순위 원칙

- **P0**: 없으면 새 IA가 성립하지 않거나, 다른 기능의 계산 기반이 되는 것. 기존 사용자가 잃는 기능이 없어야 한다.
- **P1**: 참고 앱의 핵심 경험(통계, 목표, 순서변경)과 추가 요구 중 독립 화면이 필요한 것(매트릭스).
- **P2**: 참고 앱에서 잠금/유료였던 것, 플랫폼 제약이 있는 것(알림), 만다라트.

### 6.2 릴리스 계획

#### R1 "새 뼈대" (P0) — 스키마 v3, 4탭 골격

| # | 항목 | 비고 |

## 7. 데이터 모델 v3 (UX 결정을 뒷받침하는 범위)

```js
// schemaVersion: 3
{
  habits: [{
    id, text, emoji,
    repeat: { type: 'daily'|'weekly', days: [0..6] },   // D
    trigger: { type: 'time'|'context', value } | null,
    goalIds: [],                                          // R2
    order: number,
    startDate: 'YYYY-MM-DD', endDate: null,               // 끝내기
    pauses: [{ from, to }],                               // 쉬어가기
    status: 'active'|'ended',
    reminder: { enabled, time } | null,                   // R3
    dailyTarget: 1,                                       // R3
    levels: null,                                         // R3
    mandalaRef: null                                      // R3
  }],
  checks: { 'YYYY-MM-DD': { habitId: true } },            // R3에서 number 허용
  todos: { 'YYYY-MM-DD': [{ id, text, done, time: 'HH:MM'|null, urgent: null|bool, important: null|bool, order }] },
  goals: [{ id, label, emoji, color, mandala: null | { subs: [{ title, actions: [8 strings] }] } }],
  settings: { weekStart: 1, todoView: 'list'|'matrix', clock24: true },
  schemaVersion: 3
}
```

- Firestore 문서 구조는 현행(문서 1개에 통째 저장)을 유지하되 `schemaVersion`을 추가한다. 실시간 리스너의 "local===remote" 비교는 정규화된 JSON으로 수행한다.
- localStorage 키는 `routines`→`habits`로 바꾸고, 마이그레이션 성공 후 구 키는 `routines_v2_backup`으로 1회 보존한다(복구용).

## 8. 리스크와 미결 사항

| 항목 | 리스크 | 제안 |
|---|---|---|
| 구버전 클라이언트와 Firestore 동시 사용 | v2 앱이 v3 문서를 읽어 `routines` 없음 → 렌더 깨짐, 또는 v2가 push해 v3 필드 소실 | v3 문서에 `routines` 필드를 읽기 전용 미러로 함께 저장(하위 호환), v3 클라이언트는 `schemaVersion<3` 문서를 받으면 자동 재마이그레이션 |
| 요일 반복 소급 적용 | 과거 달성률이 변할 수 있음 | 3.4절대로 소급 적용하고 릴리스 노트 명시. 필요 시 R2에서 `repeatHistory` 도입 |
| iOS 드래그 | 스크롤과 충돌 | 핸들 영역에만 `touch-action:none`, 길게 누르기 폴백 |
| 알림 | 서버 없이 백그라운드 푸시 불가 | R3에서 로컬 알림 + .ics 내보내기로 범위 축소 |
| 4탭 vs 3탭 | 목표 탭이 R1에 비어 있음 | R1은 3탭, R2에서 4탭으로 전환(탭바 위치 변경 1회 감수) |
| 전체 재렌더 방식 | 입력 중 포커스 손실(현행 이슈) | 파일 분리 시 화면 단위 부분 렌더 + 입력 필드는 제어되지 않은 컴포넌트로 |

### 코디네이터 확인이 필요한 결정 2가지
1. R1을 3탭(홈/통계 자리 비움/내정보)으로 낼지, 처음부터 4탭으로 낼지.
2. 요일 반복 변경 시 과거 기록 소급 적용(단순) vs 변경 이력 보존(정확) 중 어느 쪽을 택할지. 본 문서는 소급 적용을 전제로 한다.
